# ADR 0002: Friends-and-family logins without Tailscale

Status: exploration (branch `explore/accounts-logins`). Owner-settled points are
marked (owner); the rest is recommended shape for review, not decided.

## Settled (owner, 2026-10-01)

- Users are friends and family. They do not join the tailnet.
- Credentials are passwords plus passkeys (WebAuthn). Both, not either/or:
  password at signup, passkey enrolled later as the convenient path.
- Signup is invite codes the owner hands out. No open registration.
- No Tailscale at all (owner, 2026-10-01, supersedes the keep-both-paths
  call above). Qala runs on the owner's VPS and everybody, owner included,
  reaches it over public HTTPS with a password + passkey. The
  `Tailscale-User-Login` identity path is removed, not kept owner-only.
- Lockout recovery is owner reset only. No email, no self-service flow.

## Context

Today identity is only the `Tailscale-User-Login` header injected by
`tailscale serve` (`server/auth.ts`), and the Deno process binds loopback
only. S11 (proposed) already moves storage to per-user SQLite with
`requireUser` as the identity choke point, which is where session identity
plugs in. No data on this machine needs migration (S11).

## Recommended shape (for review)

- Sessions: HttpOnly + Secure + SameSite=Lax cookie issued at login,
  expiring server-side record. `requireUser` resolves the session cookie;
  there is no other identity source.
- Deployment: one Deno process on the VPS bound to loopback, Caddy in
  front terminating public HTTPS. Password hashes and per-user SQLite
  files live on the VPS disk, backed up to callisto.
- Passwords: Argon2id hash server-side, rate-limited login attempts.
- Invites: single-use codes with an expiry, generated by the owner;
  redeeming one creates the user row (per-user SQLite per S11) and sets
  the initial password.
- Passkeys: enrolled post-login in Settings; password stays as fallback.
- Owner reset: a CLI command on callisto that resets a user's password /
  clears passkeys in person. Nothing remote, nothing emailed.
- The owner is a regular user (first invite redeems to the owner row);
  `server/auth.ts` header auth and the loopback-only bind rule are replaced
  by session auth. `deploy/tailscale-serve.md` is retired.

## Open questions

- Coach model: `/api/llm` currently proxies to llama-server on callisto.
  With no tailnet, the VPS cannot reach it. Options are CPU inference of
  a small model on the VPS, or the coach going quiet until a hosted path
  exists.
- Public address story: domain name and who terminates TLS (Caddy
  automatic HTTPS needs a real domain).
- Session lifetime and whether a second device needs re-auth (record sync
  in S11 is already multi-device, so this is policy, not mechanism).
